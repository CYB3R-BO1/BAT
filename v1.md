# V1 Project Specification

## **Autonomous Evidence-Based Vulnerability Investigator for C Memory Bugs**

---

## 1. Project Title

**BAT: Autonomous Vulnerability Investigation, Explanation, and Correction for C Memory-Safety Bugs**

---

## 2. Project Goal (Research-Level)

Build an **autonomous vulnerability investigation system** for **multi-file C codebases** that:

1. Detects memory-safety vulnerabilities
2. Produces **valid evidence** (source → sink reachability, lifetime trace)
3. Explains the vulnerability with grounded security references
4. Suggests a patch
5. Validates the patch (compilation + optional tests)
6. Generates a final structured report

---

## 3. V1 Scope (Strict)

### Language

* **C only**

### Vulnerability Classes (Minimum 3)

1. **Buffer Overflow**

   * CWE-787 / CWE-120
   * Unsafe functions: `strcpy`, `gets`, `sprintf`, `memcpy` (without bounds)

2. **Use-After-Free (UAF)**

   * CWE-416
   * Pattern: `free(ptr)` followed by dereference or reuse

3. **Integer Overflow leading to memory corruption**

   * CWE-190
   * Pattern: `size * n` overflow passed to `malloc` or `memcpy`

---

## 4. Key Innovation

Unlike Copilot or prompt-based tools, BAT produces:

* Evidence-backed findings
* Reachability/lifetime proof objects
* Patch suggestions validated by compilation
* Grounded explanation via retrieval (CERT + CWE)

---

## 5. High-Level Architecture

```
C Codebase
   ↓
[1] Program Analysis Engine (Clang/LLVM)
   ↓
[2] Evidence Extraction Layer (facts + traces)
   ↓
[3] Vulnerability Classifier (rules + optional ML)
   ↓
[4] Autonomous Investigation Agent (tool orchestration)
   ↓
[5] RAG Knowledge Retrieval (CWE + CERT fixes)
   ↓
[6] LLM Explanation + Patch Generator
   ↓
[7] Patch Validation (recompile + retest)
   ↓
Final Report (JSON + Markdown/PDF)
```

## 6. Core Components (Modules)

---

# Module 1 — Codebase Recon Agent

### Purpose

Build structural understanding of the repo.

### Input

* Path to C project

### Output

* File/module map
* Function list
* Call graph skeleton

### Tools

* Clang AST parsing (`libclang`)

### Deliverable

`repo_index.json`

Example:

```json
{
  "files": ["main.c", "utils.c"],
  "functions": ["copy_input", "handle_request"],
  "calls": [
    {"caller": "main", "callee": "copy_input"}
  ]
}
```

---

# Module 2 — Vulnerability Hypothesis Generator

### Purpose

Find suspicious sinks and memory hazards.

### Sink List (V1)

| Bug Type     | Dangerous Sinks               |
| ------------ | ----------------------------- |
| Overflow     | strcpy, gets, sprintf, memcpy |
| UAF          | free + later dereference      |
| Int Overflow | malloc(size*n), memcpy(len*n) |

### Output

List of candidates:

```json
[
  {"sink": "strcpy", "file": "utils.c", "line": 42},
  {"sink": "free", "file": "mem.c", "line": 88}
]
```

---

# Module 3 — Evidence Extraction Engine (Most Important)

### Purpose

Construct valid evidence objects.

### Evidence Types

---

## Buffer Overflow Evidence

Required proof fields:

* Destination buffer size
* Source input controllability
* Missing bounds check

Example evidence:

```json
{
  "vuln_type": "BUFFER_OVERFLOW",
  "sink": "strcpy",
  "location": "utils.c:42",
  "buffer": "char buf[32]",
  "input_source": "argv[1]",
  "bounds_check": false,
  "taint_path": [
    "main.c:12 argv[1]",
    "utils.c:40 user_input",
    "utils.c:42 strcpy(buf,user_input)"
  ]
}
```

---

## Use-After-Free Evidence

Required proof:

* Allocation site
* Free site
* Dereference after free

```json
{
  "vuln_type": "USE_AFTER_FREE",
  "pointer": "ptr",
  "alloc_site": "mem.c:10 malloc",
  "free_site": "mem.c:20 free(ptr)",
  "use_site": "mem.c:25 ptr->data",
  "lifetime_violation": true
}
```

---

## Integer Overflow Evidence

Required proof:

* Arithmetic operation
* Potential overflow
* Used in allocation/copy

```json
{
  "vuln_type": "INTEGER_OVERFLOW",
  "expression": "len * 4",
  "location": "alloc.c:55",
  "used_in": "malloc(len*4)",
  "overflow_check": false
}
```

---

# Module 4 — Vulnerability Classification Layer

### V1 Approach

Rule-based + confidence scoring.

Optional extension:

* XGBoost classifier on extracted evidence features

Output:

```json
{
  "vuln": "BUFFER_OVERFLOW",
  "confidence": 0.92,
  "severity": "HIGH"
}
```

---

# Module 5 — Retrieval Layer (RAG)

### Purpose

Ground explanation + fix suggestions.

### Knowledge Base Contents

* CWE pages (offline text)
* CERT C Secure Coding rules
* Common safe replacements

Example retrieved chunk:

* “Avoid strcpy; use strncpy with bounds.”

RAG input query:

```
CWE-787 strcpy safe replacement patch
```

RAG output:

* Relevant fix templates
* Security references

---

# Module 6 — LLM Explanation + Patch Generator

### Input

* Evidence JSON
* Retrieved security context

### Output

* Explanation
* CWE mapping
* Exploit scenario
* Patch diff

Example:

```diff
- strcpy(buf, user_input);
+ strncpy(buf, user_input, sizeof(buf)-1);
+ buf[sizeof(buf)-1] = '\0';
```

LLM must not hallucinate detection. Only explain evidence.

---

# Module 7 — Patch Validation Agent

### Steps

1. Apply patch in temp branch
2. Recompile project
3. Re-run analysis to confirm bug removed

Validation output:

```json
{
  "patch_applied": true,
  "compilation": "SUCCESS",
  "vulnerability_fixed": true
}
```

## 7. Autonomous Agent Workflow (Core Loop)

```
for each candidate sink:
    build evidence
    classify vulnerability
    retrieve fix knowledge
    generate patch
    validate patch
    write report entry
```

Stopping condition:

* Evidence must be complete OR finding discarded.
